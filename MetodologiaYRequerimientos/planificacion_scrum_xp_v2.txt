1. Vision General del Proyecto
Se aplica una combinacion de Scrum (marco de gestion iterativa) con practicas de Extreme Programming (XP) para garantizar entregas de alta calidad en un plazo muy ajustado. El equipo esta compuesto por 7 personas con roles claramente definidos, 3 duos de pair programming y un Tech Lead que opera en solitario sobre el modulo mas critico (auth-api).

La meta es tener el sistema funcional y desplegado el 12 de mayo, dejando 3 dias de buffer (13-15 May) para afinamiento, polish de UI y demo final. El Sprint 0 (26 Abr) es ejecutado exclusivamente por Allen para dejar el entorno 100% listo antes de que el equipo completo arranque el Sprint 1.

16. Herramientas del Proyecto
Control de versiones: Git + GitHub. Ramas: main, staging, develop, feature/US-XX.
Monorepo: TurboRepo con paquetes auth-api, bus-api, ticket-api, frontend-web, frontend-pwa, packages/database.
CI/CD: GitHub Actions (lint + test + build por paquete) + Vercel/Railway (deploy automatico a staging).
Tablero Kanban: GitHub Projects o Trello. Columnas: Backlog / En progreso / En revision / Hecho.
Comunicacion: WhatsApp/Discord para daily async + Google Meet para ceremonias.
Testing: Jest + React Testing Library. Juan lidera los tests de integracion y E2E.
Estimacion: Planning Poker (escala Fibonacci: 1, 3, 5, 8, 13). Tomas Solis facilita.
Documentacion: README en GitHub (Allen) + API docs (Andrew en buffer final).
